# 图纸上传助手（分发版）

这个程序只负责读取“图纸上传包”并把图纸上传到 CAXA。它不包含 Qwen、
视觉模型、PDF 识别或整页拆分逻辑。

## 环境

- Windows
- 已安装 CAXA 协同管理 2011 客户端
- 当前用户具备 CAXA 图纸新建/修改权限
- 能访问 CAXA 服务器，默认 `192.168.1.28:8900`

## 使用

1. 双击当前版本化 EXE。
2. 二选一准备图纸：
   - 打开识别助手导出的上传包；
   - 或由同事自己拆分、重命名后，直接把 PDF 拖入窗口。
3. 文件名建议严格为“图号 名称.pdf”，例如：
   `01.59.OV.03 焊接管路包.pdf`；单字母工艺文档为 `Z03.xxx.pdf`。
   不符合规则的行会标红并禁止上传。
   如果只是图号/名称字段被手工修改，界面会显示“将按规范文件名上传”，
   程序会把**你选中的那份内容**复制到本任务暂存目录后按规范名上传，
   不会改名或覆盖你的源文件，也不会改用同名的其他旧文件。
4. 填写当前同事自己的 CAXA 用户名和密码；密码可以为空。
5. 默认重复图号策略为 `append_iteration`，等同界面中的
   “在现有版本上追加新的版次”。程序会回读版次是否真的增加；没有增加的
   记为“待核实”，不会当成成功。
6. 需要时勾选“上传成功后发起审核打印流程”，并填写当前环境中的审核人。
   流程关联包括本批已确认的 Drawing 和 CappDocument（J03/M03/Z03 等），
   不会只带总图。
7. 点击“上传图纸”。

程序每天第一次启动会在后台检查 GitHub 最新正式版本。发现新版后，点击
“下载 vX.Y.Z”，程序会校验 GitHub SHA-256，自动覆盖当前 EXE 并重启新版。
旧 EXE 保留为同目录 `.old-时间戳` 备份。
更新保持原路径和文件名不变，桌面与开始菜单快捷方式继续有效。

`03.GPZ.*` 图纸自动挂到 CAXA 既有目录 `GPZ钢瓶组`，不需要手工改成
`GPZ系列`。

## 借用与次级条目

- 关系直接显示在“上传图纸”层级树中：
  - 普通零件先在 Product `01 通用件` 下按图号建立归属路径；
  - 每个零件最多一个 `reference=False` 归属父级；
  - `01.x.*` 子件挂到同一 `01.x.*` 系列父级时默认归属；`x` 不同才默认借用；
  - 03 整机、其他跨图号上级都使用 `reference=True` 借用，可同时有多个；
  - 选中关系行后可人工切换归属/借用，人工选择优先。
- 03 整机属于各自系列 Product，不放在 `01 通用件` 下。一批可有多台 03 整机；
  层级树按系列产品目录分组，同一目录下的多台 03 整机都显示为目录子级。
- 双击对应 03 整机行填写系列产品名称；程序用整机图号作为产品代号创建该
  Product，多台 03 的产品名称互不覆盖。
- 没有 03 整机图、只有 J03/M03/P03/T03/Z03 工艺文档时，层级树仍会生成
  系列产品节点。产品名称可从产品节点或相应工艺文档行填写；Product/整机 Part
  缺失时按既有系列目录补建，再把 CappDocument 挂到整机 Part。
- Product 已存在但整机 Part 缺失时只补整机 Part，不要求重复填写产品名称。
- `J02/M02/P02/T02/Z02` 工艺文档同时受支持。`02.A36.02.AR02` 这类图号
  从最近点号 `02.A36.02` 向上寻找已存在的 Part 上级；叶子缺失时只创建末级
  Part 并挂到最近上级，不直接挂到 Product `02 半成品`。
- 新产品按系列目录挂载：`03.HW.* → HW系列`；
  `03.HT.HGB.* → HT合同特殊/HGB系列`，其他 `03.HT.* → HT合同特殊`。
  上传端不允许创建系列目录；目标目录必须已在 CAXA 中存在，否则预检和上传
  都会在上传任何对象前报错。
- 新建或复用整机零件时，Part 的“物料编码”统一写入图号；已有值不一致会更新，
  写入后立即回读确认。
- `Z03.*` 等工艺文档只挂到整机 Part，不会把工艺文档编号写入整机物料编码；
  整机 Part 的物料编码始终使用对应的 `03.*` 整机图号。
- `Z02.*` 工艺文档可挂到 Product `02 半成品` 下已存在或按上述规则新建的
  `02.x.*` Part；目标或分组存在多个原件时阻止上传。
- 同一 02 图号只能有一个原件。多个产品/上级挂接合法，但只能有一个
  `reference=False` 归属，其他必须是借用；多个非借用归属时预检和上传阻止。
- 借用关系只链接已经存在的零件；新零件必须先由本批上传在通用件层级建立。
- 同一个子件可以借用到多台整机或多个组件。所有关系写入后会再按完整关系集
  回读一次；任何一条缺失都会自动补建，补建后仍缺失则阻止发起流程。
- 03 Product 按图号直接精确查询；自动归属/借用按图号规则判断，不再逐条读取
  设计树，以提高预检和上传速度。
- 先把一批 PDF 全部拖入列表，再在树内把子 PDF 行拖到父 PDF 行上。
  拖动时显示 PDF 拖动标签，经过的上级行高亮，松开后高亮消失。
  也可以右键父级 PDF，选择“增加次级条目”。
- 可按住 `Ctrl`/`Shift` 多选多个子图，再一起拖到父级。
- 预检若发现图号在 CAXA 中已有原件，会把归属计划自动改成借用；
  “只升版”列可选择：
  - `☑ 不借用`：只给已有原件追加版次，不写任何关系；
  - `☐ 升版并借用`：先升版，再借用到当前设置的上级。
  没有设置关系时默认只升版；没有上级却选择升版并借用会阻止上传。
- 上传前若已有 Drawing 仅缺少 `.pdf`、其余名称完全一致，程序会通过图纸属性
  自动补后缀并回读确认后再升版。
- 右键“增加次级条目”只接受 CAXA 设计树中已有图号，固定建立
  `reference=True` 借用；子项不存在时跳过并报错，不新建 Part。
- 导入时若本批存在子图号的直接上级，例如
  `01.21.01.SFD2-17-01-03-01` 与 `01.21.01.SFD2-17-01-03`，程序会自动建立父子关系；
  已有显式关系优先，不会覆盖人工指定。
- 拖到新的归属父级会替换原归属；借用父级不会被一起删除，可以保留多个。
- 双击行的文字区域可修改图纸信息；双击行首 `+`/`-` 只展开或折叠，不弹修改框。
- “增加次级条目”对话框居中显示在主窗口。
- 右键图纸行可直接在树内覆盖修改“图号 名称”；双击及“修改完整信息…”打开
  居中于主窗口的完整编辑对话框。
- 完整编辑对话框中的系列产品名称、系列产品目录会显示灰色示例；示例只是
  输入提示，不会保存或上传。
- 右键图纸行可选择“从列表中删除所选图纸”，支持保留当前一条或多条选择。
  该操作只修改本地上传计划，并清理相关归属/借用关系和手工借用记录；
  不删除本地 PDF，也不删除 CAXA 远端对象。系列目录、产品节点和外部
  CAXA 节点不能作为图纸删除。
- 右键系列行或产品行只修改本地上传计划，不读取或改写 CAXA 已有对象。
  上传时系列目录必须已存在；Product 可复用或挂入该既有目录后新建。
  `03.HT.HGB.*` 使用二级目录 `HT合同特殊/HGB系列`。
- 新建的归属子件会挂到你选定的父级；显式父级不存在会直接报错，不会猜
  另一个父级。
- “执行手动借用”只处理设计树中已经存在的图号；缺失节点会跳过并显示。
- 上传成功但忘记自动发起“审核打印”时，可勾选对应图纸并点击功能区
  “发起流程”。该按钮只使用本机已确认的上传和关系记录，不会重新上传 PDF；
  本地 PDF 已移动或删除也可使用，存在未确认项时会直接阻止。

## 任务记录、重复提交与待核实

- 每次上传都会在本机写入一个轻量 SQLite 任务日志（默认在
  `%LOCALAPPDATA%\caxa_upload_journal`），记录服务器、账号、文件哈希、
  已确认的 Drawing/版次/关系/流程 ID。
- 同一批内容再次点击上传：不会重复建版次或流程，会提示“该批次已完成”；
  只改关系或只补发流程也不会重传 PDF。需要重新提交时，内容变化或账号/
  服务器变化会自动形成新任务，或在提示里选择“作为新任务重新提交”。
- 超时、helper 退出、写入后回读失败等“结果不明”的操作会标为
  **待核实**，程序不会自动重放。请先在 CAXA 中确认，再用界面按钮
  “核实待定结果”。界面会按图号/目标文件名自动回读文档 ID、类型和版次，
  不要求填写 CAXA 后台 Object ID 或 `1002/1003`；流程通常只需确认界面中
  可见的流程实例 ID，关联文档由程序自动读取和比对。

  命令行工具保留给维护人员诊断使用：

  ```
  python upload_recover.py list
  python upload_recover.py confirm --task <任务号> --kind upload --key 01.01 --remote-id 123456 --class-id 1002 --iterator 3
  python upload_recover.py no-write --task <任务号> --kind upload --key 01.01 --note "CAXA 中确认未写入"
  ```

  只有被核实的那一条会改变；其它已确认成功不会重做。
- “核实待定结果”窗口使用业务名称显示图纸上传、次级/借用关系和审核打印
  流程；流程会优先显示实例 ID、状态与关联文档数。所有待核实操作合并在
  同一张列表中，可多选处理，不会每张图纸弹一个窗口。
- 人工确认某次上传未写入后，该行恢复为“待上传”，可以回到主界面点击
  “开始上传”；窗口也提供“全部确认未写入并重新上传”按钮直接重试。
- 任一必需关系失败、缺失或待核实时，即使勾选了“发起流程”也不会自动发流程。

## 自动确认导入/重复对话框

- 仅在本次“上传图纸”命令执行期间、且只处理 helper 自己进程中的窗口。
  重复对象框还要匹配精确标题、正文、当前目标文件名和唯一窗口，不会跨进程
  点击用户手动发起的弹框。
- 反审后的图纸只要当前状态回到“设计”，即使仍保留旧流程关系，也允许继续
  追加版次。
- “导入文件确认对话框”出现时自动点击“确定(O)”；按按钮类、归一化文本和默认按钮
  逐级识别，失败时记录完整子控件信息，不点击其他窗口。
- 通过 UI Automation 选中真实的“在现有版本上追加新的版次”RadioButton，
  再勾选“应用到所有”并点击“确定”；每一步都回读控件状态，不明确或多处
  命中时不点击，改由人工确认。

## 新设备首次注册

- 新设备第一次上传前会主动注册 32 位 `PlmComApi.dll`，必要时弹出一次 UAC；
  同一设备后续上传不再执行任何 COM 检查，减少登录等待。
- 注册成功后的设备标识与 `registration_id` 写入 `journal.sqlite3` 的
  `device_state` 表。`python upload_recover.py device` 可查看。
- 注册失败或取消 UAC 不会写标记。CAXA 重装/注册损坏时可设置
  `CAXA_FORCE_PLM_REGISTRATION=1` 后再上传一次，强制更新标记。
- helper 会自行把 CAXA EAP `bin` 和 `template\script` 加入进程 PATH，
  用于解决 `PlmComApi.dll` 文件存在但依赖 `BCGControls.dll` 等找不到，
  `regsvr32` 报 `0x8007007E` 的问题。

## 账号安全

密码使用当前 Windows 用户的 DPAPI 加密后写入程序同目录的
`config.json`，不能直接复制到另一台电脑解密。密码允许为空；空密码同样
会覆盖并保存为空凭据，不会沿用旧密码。

## 构建（工作设备）

```
powershell -ExecutionPolicy Bypass -File ..\build_all.ps1 -All
```

helper 需 CAXA 2011 引用 DLL，本机会明确报缺依赖；不要用旧 exe 充当新版本。
