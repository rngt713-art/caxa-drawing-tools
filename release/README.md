# CAXA 图纸上传助手 v1.2.5

本 Release 只提供编译后的上传端 EXE 和本说明。源码请从 GitHub 仓库 clone：

```text
https://github.com/rngt713-art/caxa-drawing-tools.git
```

## v1.2.5 更新

- 03 整机改为 Part 优先：先用 CAXA 零部件索引精确查询整机 Part。
- 整机 Part 已存在时直接复用，不再解析 Product，也不要求产品名称或目录。
- 整机 Part 不存在时，产品名称变为人工必填；按输入名称快速查询已有 Product，
  命中且目录唯一时复用，未命中才新建 Product。
- 新增 CAXA 高级 `ProductPartLink` 查询，可按整机 Part 返回实际 Product 和目录。
- 产品名称查询不再加载整个 Product 目录索引。
- `03.HT.HG025-350W` 等普通 HT 整机固定映射到 `HT合同特殊`；不会误映射到
  `HT系列`。
- 每批已有整机只做 `query_parts`，不会再为每台整机遍历设计树或 ProductFolder。

## 运行环境

- Windows
- 已安装 CAXA 协同管理 2011 客户端
- 当前账号具备 CAXA 图纸新建、修改和关系维护权限
- 能访问现场 CAXA 服务器

## 使用

1. 双击 `图纸上传助手.exe`。
2. 填写当前使用人的 CAXA 用户名和密码；密码允许为空。
3. 打开识别端导出的上传包，或拖入按 `图号 名称.pdf` 命名的 PDF。
   拖入文件夹时只读取该文件夹第一层的 PDF，忽略子文件夹和非 PDF 文件。
4. 检查文件名、文档类型、所属图号、层级和借用关系。
5. 点击“规范并预检”；文件名、指纹和本地检查通过后再连接 CAXA 预检。
6. 预检通过后点击“开始上传”。
7. 需要发起审核打印时，填写审核人并勾选“上传成功后发起审核打印流程”，
   或上传完成后使用“发起审核打印”。

程序始终上传用户选中的原始内容副本，不会改名或覆盖源 PDF。同一批内容再次
提交不会重复上传已确认成功的图纸。

## 更新

- 每天第一次启动时，程序在后台检查 GitHub 最新正式 Release。
- 发现新版后，界面按钮显示“下载 vX.Y.Z”。
- 点击后下载版本化 EXE，校验 GitHub 提供的 SHA-256；校验通过后等待当前进程
  退出，直接覆盖当前 EXE 并自动重启新版。
- 更新保持原 EXE 路径和文件名不变，已有桌面/开始菜单快捷方式继续有效。
- 旧 EXE 会在同目录保留为 `.old-时间戳` 备份；新版启动失败时不会把旧文件
  当作成功更新。

## 02 半成品层级

- `02.A36.02.AR02` 从最近点号上级 `02.A36.02` 开始向上寻找已有 Part。
- 只创建缺失的末级 Part，并挂到最近上级。
- 同一图号只能有一个原件。
- 多个产品/上级挂接合法，但只允许一个 `reference=False` 归属，其他必须是借用。

## GPZ 特殊系列

- `03.GPZ.*` 自动映射到 CAXA 既有目录 `GPZ钢瓶组`。
- 不再生成或要求手工修改为 `GPZ系列`。
- GPZ 产品显示名称中的 `/` 属于名称，不影响整机代号识别。

## 外部 Agent 接入边界

- 本程序只负责上传，不负责 PDF 识别、拆页或 OCR。
- 自动确认 CAXA 导入框和重复对象框依赖 helper PID、当前 login/upload 命令和
  精确目标文件。外部 Agent 直接启动 helper 或从其他进程模拟点击时不会生效。
- 外部 Agent 不得绕过该限制点击无关窗口、重放部分写入或自行修改 CAXA 数据。
  遇到“待核实”应停止并交用户核实。
- 推荐流程：外部工具完成拆分并生成规范 PDF/上传包，用户通过本程序界面预检和
  上传。无法满足这些边界时，应停止并请求人工处理。

## 待核实

超时、helper 退出或写入后回读失败时，操作会标记为“待核实”，程序不会自动重放。
请在“核实待定结果”窗口中回读 CAXA 证据，或人工确认未写入后再重试。

## 日志与配置

- 配置：程序目录 `config.json`
- 任务日志：`%LOCALAPPDATA%\caxa_upload_journal\journal.sqlite3`
- 密码使用当前 Windows 用户的 DPAPI 加密，不能直接复制到其他电脑解密。
