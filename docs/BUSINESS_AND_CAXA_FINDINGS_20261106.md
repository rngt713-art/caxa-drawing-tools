# CAXA 图纸工具业务与真机发现

更新时间：2026-11-26

本文用于说明当前业务目标、已经实现的操作规则、真实 CAXA 小批上传结果
和仍需确认的事项。

## 1. 业务目标

工具分为两部分：

1. 本机识别助手：调用本地视觉模型识别扫描/PDF 图纸，拆页、命名、
   人工核对后导出 `manifest.json + drawings/*.pdf` 上传包。
2. 图纸上传助手：可独立分发，不依赖视觉模型；可导入上传包或直接拖入
   已拆分 PDF，上传到 CAXA 协同管理 2011。

上传端还要完成：

- 建立或复用图纸对应的 Part；
- 维护 Part 的归属/借用关系；
- 将 03 整机图纸和 Z03 工艺文档挂到整机 Part；
- 处理重复图号版次；
- 全部成功后可发起“审核打印”流程；
- 对超时、丢响应、回读失败等结果不明操作标记“待核实”，不自动重放。

## 2. 当前业务规则

### 2.1 文件名

- 数字图号：`图号 名称.pdf`，例如
  `01.59.OV.03 焊接管路包.pdf`。
- 单字母工艺文档：`图号.pdf`，例如 `Z03.OV.04-05030.pdf`，不带中文名。
- 图号与名称之间只能有一个半角空格。
- 不符合规则的行标红并禁止上传。

### 2.2 普通零件归属

- 普通 Part 应位于“通用件”业务范围内，并参考图号前缀和现有树结构。
- 每个 Part 最多一个 `reference=False` 归属父级。
- 图号最近前缀父级属于归属关系，例如
  `01.21.01.SFD2-17-01-03-01` 可归到
  `01.21.01.SFD2-17-01-03` 下。
- `01.x.*` 子件挂到同一 `01.x.*` 系列父级时，即使剩余图号不是文本前缀，
  也默认建立 `reference=False` 归属；`x` 不同时默认借用。
- 找不到本批父图时，运行期会根据 CAXA 已有前缀 Part 继续匹配；
  没有可用前缀时按当前上传逻辑创建/挂接。
- `04` 开头的组件不是独立于通用件；用户已确认本次六个 04 Part 的位置正确。
- 焊管包、支架包等非 `04` 组件也属于通用件业务范围，可借用到整机。

### 2.3 借用

- 借用关系为 `reference=True`，可以有多个父级。
- 03 整机下组件、跨图号复用、焊管包/支架包挂整机均属于借用。
- 同一 Part 的归属父级只能有一个，但借用父级可以多个。
- 在 UI 中拖到新的归属父级时替换旧归属，不删除其他借用关系。

### 2.4 03 整机与系列产品

- 03 整机不在普通通用件 Part 树中，而在各自系列 Product 下。
- 历史描述“Product 的产品代号通常等于 03 整机图号”不能作为查找依据；
  2026-11-26 现场数据已确认 Product `IdentityNo` 可能只是整机图号前缀或沿用
  其他历史值。当前匹配规则见 §8。
- 一批图纸可以包含多台 03 整机。上传端按系列产品目录分组，
  同一目录下的多台 03 整机作为该目录子级，并在每台 03 行单独编辑产品名称。
- 新建 Product 必须挂到对应系列产品目录：
  - `03.HW.*` → `HW系列`；
  - `03.HT.HGB.*` → `HT合同特殊/HGB系列`；
  - 其他 `03.HT.*` → `HT合同特殊`；
  - 其他系列默认 → `<系列字母>系列`。
- 上传时先查找目标系列目录；目录必须已存在，上传端不得创建。
  目录缺失时先阻止上传；目录存在时再将 Product 挂入目标目录。
- 示例：
  - Product identity：`03.HE.002035A-21B01`
  - Product 名称：`HEM0.2-35(标准型)`
  - 其下 Part：`03.HE.002035A-21B01 氦气压缩机`
  - 03 整机下多个 04 组件均为 `reference=True` 借用。
- 系列产品名称默认允许为空。
- 预检发现 03 整机对应 Product 不存在的，系列产品名称变为必填。
- 产品不存在但名称已填时，以整机图号为 Product identity 创建 Product，
  再在其下创建/挂接整机 Part。
- 新建或复用整机/组件 Part 时，将“物料编码”设置为该 Part 图号；
  已有值不一致会更新并回读确认。CAXA EAP 中对应属性为 `MaterialNo`。
- 同一子件可以借用到多个上级。借用关系使用独立 Part2Part 链接；整批关系
  写完后再做一次全局回读，防止后续写入影响先前关系。
- W6 系列当前无权限且不会进入上传范围，不做特殊处理。

### 2.5 Z 工艺文档

- `Z03.*` 按 `CappDocument` 上传到对应 03 整机 Part。
- 单字母工艺文档从图号确定整机代码。
- 本次 Z03 已成功挂到整机加工艺文档，但未加入流程的 Drawing 集合；
  流程当前只关联 Drawing 文档。若业务要求工艺文档也进入流程，需要单独确认。

### 2.6 手工增加次级条目

- 应为“链接 CAXA 已有零件”，而不是新建 Part。
- 当前对话框固定：
  - `link_type=borrow`
  - `reference=True`
  - `manual_override=True`
  - `link_only=True`
- 不再从本批 PDF 下拉选择，要求输入 CAXA 设计树已有图号。
- 缺失子项在预检中列出，执行关系时返回“缺子”并阻止后续流程。
- 手工借用父级不再写入 `item.parent_code`，避免污染零件自身归属。

### 2.7 上传端 UI

- 上传列表和关系合并为同一棵可展开层级树。
- 支持 `Ctrl`/`Shift` 多选后批量拖到父级。
- 拖动时显示 PDF 标签，目标父级行高亮，松开后清除。
- 双击行首 `+`/`-` 只展开/折叠；双击文字区域才打开修改信息。
- 每台 03 整机行可单独填写系列产品名称；多台 03 不共享顶部单一字段。
- 新建 03 Product 后，同一任务内缓存产品对象，后续工艺文档和借用关系直接复用，
  避免刚创建的 Product 尚未出现在产品树扫描结果中而误报“整机不存在”。
- 层级树按系列目录分组：多个同一系列的 03 整机位于同一个产品目录节点下。

### 3.3 `part_info` 的字段限制

- `part_info.parents[].parent_identity/parent_name/parent_id` 有时为空，
  但 `reference` 可读。
- 需要确认具体父级时，`link_endpoints[].roleA/roleB` 比 `parents` 更可靠。

首次日志显示自动确认已识别到对话框，但
`ClickUniqueChild(dlg, "确定")` 返回 False，当时由用户手工点击。

- 按钮必须属于 `Button` 控件类；
- 按钮文本先归一化，兼容 `确定(O)`、`&确定`；
- 唯一命中后发送 `BM_CLICK`；
- 找不到时尝试默认按钮 IDOK；

- 历史旧版只处理上传命令期间、当前 helper 进程属于的窗口；2026-11-12 起

### 3.5 重复对象与已发布图纸

- 自动追加版次对话框要求先确认“追加新的版次”，再点“确定”。
- 如果无法唯一识别单选框或按钮，不应盲点。
- 已发布图纸不允许追加版次，工具应在写入前拦截。
- 本次真实批次没有触发重复对象追加对话框，因此该路径仍需继续现场覆盖。

### 3.6 CAXA 会话与多账号

- 客户端已登录一个账号时，CAXA 可支持 helper 再以另一个业务账号登录。
- 但客户端停在“确定退出系统吗？”等模态框时，helper 登录可能长时间无响应。
- 取消退出模态框后，测试账号 helper 登录恢复正常。
- 因此排查登录超时时，应先检查 CAXA 客户端是否被退出/授权/模态窗口阻塞。

## 4. 防重与恢复

- 同一内容批次、服务器和账号会复用本地任务记录，不重复上传或重复发流程。
- 仅修改关系或补发流程时，不重新上传已确认 Drawing。
- 上传、关系、流程结果分别为三阶段记录。
- 超时、helper 退出、写入后回读失败会记为“待核实”。
- “待核实”会阻止自动重放，必须人工核实后处理。
- 本轮补发流程复用了任务 `T20261106123504-1365e7`，没有重复上传
  7 张 Drawing。

## 8. 2026-11-26 高级查询抓包与 ProductPartLink 反查

CAXA 客户端“高级查询”抓包确认：查询直接发送到 SQL Server `1433/tcp`，
不经过原来的 EAP RPC `8900/tcp`。捕获到的核心联表条件为：

```sql
SELECT DISTINCT a.*
FROM T_Product a, T_Part b_1, T_ProductPartLink c_1
WHERE a.OBJ_ID=c_1.ROLEA_ID
  AND b_1.OBJ_ID=c_1.ROLEB_ID
  AND b_1.IdentityNo LIKE @P1
```

这是 CAXA 客户端内部的高级查询实现证据，不是本工具可使用的新接口。
生产工具不得直接连接 SQL Server，也不得保存或要求用户填写数据库账号；
继续复用已登录的 CAXA EAP SDK 完成同样的对象关系查询。

当前 SDK 查询路径：

1. `query_parts` 先精确确认整机 Part。
2. helper 命令 `find_product_by_part` 通过
   `ObjectStore.NewQuery()` + `QueryCondition` 反查 Product。
3. `ProductPartLink` 两侧角色固定为：
   - Product 侧 `ProdWithTopAssembly`；
   - Part 侧 `TopAssemblyInProd`。
4. Python 端 `products_by_machine_part()` 接收 Product 的对象 ID、图号和名称。
5. `product_folder_paths()` 返回该 Product 的真实 ProductFolder 路径；
   helper 在单个会话内缓存完整 ProductFolder 映射，避免每个整机重复遍历。
6. `find_product_for_machine()` 采用 Part 优先路径。高级关系查询成功时，
   不再加载旧版约 1722 个 Product 的全产品索引；查询失败时才走精确查询和
   名称/目录兼容回退。

现场已验证的 Product/Part 关系包括：

- `03.HT.HGB05-05025B` Part `44135` → Product
  `687 / 03.HT.HGB05-05025` → `HT合同特殊/HGB系列`。
- `03.HX21.E20H-03L` Part `44510` → Product
  `1377 / 03.HX21.E20H-01` → `HX系列`。

因此不能把 Product `IdentityNo` 与整机 Part `IdentityNo` 做简单等值匹配，
也不能根据图号推断 `HX21系列`、`HGB系列` 等目录；必须读取实际
`ProductPartLink` 和 ProductFolder 路径。

## 9. 2026-11-26 ProductFolder 系列索引

现场确认系列 ProductFolder 数量固定、变化极少，可由 helper 在预检会话中
读取一次并缓存，不需要继续维护逐项图号映射规则。

- helper 命令 `product_folder_index` 返回每个目录的对象 ID、名称、完整路径、
  路径层级和 `path_parts`。
- Python 按图号中的字母段与目录名中的拉丁字母匹配：
  - `LSYZ两室一站` → `03.LSYZ.*`；
  - `GPZ钢瓶组` → `03.GPZ.*`；
  - `QT其他成品` → `03.QT.*`；
  - 顶层精确 `NS` 目录匹配 `03.NS.*`；
  - `SFC防爆箱`、`SFD防爆箱` 是独立目录；
  - `NS防爆箱` 是历史遗留目录，不做自动匹配；需要放入其中的图纸由操作员手动
    修改；
  - `HT合同特殊/HGB系列` 通过两级路径匹配 `03.HT.HGB01-*`。
- `OM/OV/OW` 全部映射到 `OW系列`。
- `W6` 是设计图纸区域，不参与整机系列自动匹配；出现时保留“未指定系列”，
  由操作员手工设置。
- 该索引只在当前 helper 会话内缓存。新增或修改目录后重启 helper 即可重读，
  不需要改代码。
