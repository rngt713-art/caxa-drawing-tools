# CAXA 图纸工具业务流程与需求基线

本文档是跨会话、跨窗口唯一权威的业务规则基线。任何代码改动、重构或外部评审落实前，必须遵循本文的规则优先级与硬性边界。

---

## 1. 规则优先级与安全边界

1. **业务现场结论优先**：用户在真实业务现场确认的规则优先于通用架构建议、代码审查意见和编程偏好。
2. **刻意兼容设计不得误删**：本文标注为“刻意设计”“兼容回退”“不得移除”的实现不是待修 bug（例如高层 `LinkSubPart` 失败后先回读再走低层 `NewOneLevelLink(1037)` 回退）。
3. **禁止直连数据库**：已抓取确认 CAXA 客户端高级查询直接连接 SQL Server `1433/tcp`，但生产工具**严禁**直连 SQL Server，也不得保存或要求用户输入数据库账号；所有查询必须通过已登录的 CAXA EAP SDK 执行。
4. **单机恢复定位**：SQLite 操作日志与进程锁只保证单机防重与崩溃恢复，不承诺跨机器 exactly-once；同一批图纸应由同一名操作员提交。
5. **公开仓库脱敏原则**：源码、文档与默认配置不得包含真实人员姓名、密码、Token、DPAPI 密文、SQLite 数据库、业务 PDF 或私钥；说明中统一使用 `上传账号A`、`审核账号`、`测试账号` 等角色占位。

### 账号职责与空密码支持

- 常规上传测试使用 `测试账号`；业务审核由 `审核账号`（Person ID `66`）承担；独立主管审核工具必须使用审核人账号。
- CAXA 服务器地址、端口与用户名必填；**密码允许为空串**以兼容未设置密码的现场账号。清空旧密码后必须保存空字符串，不得静默沿用旧 DPAPI 密文。

## 2. 文件命名、分类与上传包校验

- **数字图号图纸**（`01.*`、`02.*`、`03.*`、`04.*`）：规范文件名为 `图号 名称.pdf`，图号与名称之间**只能有一个半角空格**。
- **单字母工艺文档**（`Z02.*`、`Z03.*`、`J02.*`、`J03.*`、`M02.*`、`M03.*`、`P02.*`、`P03.*`、`T02.*`、`T03.*`）：规范文件名为 `图号.pdf`，**不带中文名称**。
  - 若原图/OCR 带有中文名，识别/导出与「一键规范文件名」应裁去中文名，展示名称可保留在 `display_name`，规范 `name` 与目标文件名保持一致。
- **多字母错误前缀**：`ZJ03.*` 等多字母前缀按当前规则**拒绝上传并标红**，必须先由人工修正图号；未获业务单独确认前不得擅自放宽。
- **`.pdf` 后缀规则**：保留 `.pdf` 后缀是当前规范行为（早期无后缀 Drawing 属于历史旧版行为）。若 CAXA 中历史 Drawing 仅缺少 `.pdf`（去掉 `.pdf` 后名称与目标完全一致），允许 helper 自动通过属性编辑补全 `.pdf` 并回读确认，其余名称差异一律不改并阻止。
- **一键规范与迁移**：
  - 点击「规范并预检」保留文件名合规图纸的手动取消勾选状态；若导入后同路径 PDF 内容发生变更，须经操作员确认后才采用新 SHA-256 与文件大小。
  - 「一键规范文件名」改变图号后，必须同步迁移 `items`、`relations`、`manual_borrows` 中的图号引用并重算 `kind` 与成品代码（`machine`），避免旧图号残留在计划中造成悬空关系。
- **选中行校验边界**：仅对勾选执行的行执行严格字段与文件存在性校验；未勾选的异常行可保留在清单中待人工修正，不阻塞其余有效批次。

## 3. 普通零件（`01` 通用件 / `04` 虚拟件）归属与借用

- **唯一原件原则**：同一图号在 CAXA 中只能存在一个原始 `Part`。界面树上同一个 Part 若出现两次，说明被重复设置了 `Reference=false` 挂接而非存在两份零件实体。
- **唯一归属 + 多借用**：
  - 每个 Part 最多只能有一个 `reference=False`（`own`）归属父级；
  - 同一个 Part 可以同时拥有多个 `reference=True`（`borrow`）借用父级。
- **自动推导默认规则**：
  - 导入时按图号直接上级前缀自动建立层级（如 `01.21.01.SFD2-17-01-03-01` 归属到 `01.21.01.SFD2-17-01-03`）。
  - 同属 `01.x.*` 同一系列的父子关系默认建立 `reference=False` 归属；跨系列默认 `reference=True` 借用。
  - 普通新零件先在 Product `01 通用件` 下按图号最近已有前缀建立归属路径；找不到可用前缀时挂在 Product `01` 下作为根 Part。
  - `04` 开头的虚拟件组件同样属于通用件业务范围；挂到 `03.*` 整机或其他跨图号上级时默认建立 `borrow`。
  - 人工选择（双击切换、拖拽变更父级）生成 `[人工]`（`manual_override=True`）锁定，永远优先于自动推导，重复预检不得覆盖；删除的边不会在再次归一化时复活。
- **借用与手工次级条目边界**：
  - `borrow` 关系与「增加次级条目」（固定 `link_type=borrow`、`reference=True`、`manual_override=True`、`link_only=True`）只能链接 CAXA 中**已经存在**的节点，禁止为建立借用而新建缺失父/子 Part；缺失时明确报错（缺父/缺子）并阻止自动流程。
  - 手工借用父级不写入 `item.parent_code`，避免污染零件自身归属。
- **已有原件与真实关系预检**：
  - 判断是否为“已有原件”**必须**按 Part `IdentityNo` 查询设计树，不得仅凭 Drawing 名称判断（防止历史无 `.pdf` 后缀 Drawing 导致误判）。
  - 预检与写前检查都会读取父件当前实际子关系：
    - 父级下已存在同一条 `reference=False` 关系 → 保留 `own`（界面显示“已有归属关系”），默认勾选 `upgrade_only=True`（☑ 仅升版），不重写关系；
    - 父级下已存在同一条 `reference=True` 关系 → 保留 `borrow`（界面显示“已有借用关系”），默认勾选 `upgrade_only=True`；
    - 已有原件在当前父级下**尚无**该条关系时，才将计划中的 `own` 强制转为 `borrow`（防止同一 Part 出现第二个 `reference=False` 归属）。
  - 已有原件行提供「只升版 / 升版并借用」切换（并由 `upgrade_only_user_set` 保持人工选择）：无计划关系默认勾选「不借用」，有计划关系默认不勾选；取消勾选「只升版」但没有合法父级时，写前阻止上传。

## 4. `03` 整机、系列产品（Product）与系列目录（ProductFolder）

- **`03.*` 整机查询优先级（Part 优先）**：
  1. 预检和写前检查首先按整机 `03.*` 图号精确查询 Part；
  2. **唯一命中**时直接复用该 Part ID，跳过 Product 名称、系列目录解析与建产，且**绝不**按图号推断的目录去移动或重挂已有 Product；
  3. **多条命中**时报错阻止（`machine_part_duplicate`），交人工清理；
  4. **未命中**时才进入 Product 解析与新建路径，此时系列产品名称变为人工必填。
- **Product 查找与消歧**：
  - 允许通过 `ProductPartLink`（`ProdWithTopAssembly` / `TopAssemblyInProd`）结合实际 `ProductFolder` 路径定位已有 Product，不再加载全库上千个 Product 索引，也不假设 `Product.IdentityNo == 整机图号`。
  - 未命中且已填产品名称时，按产品名称精确查找；命中多个同名候选时，必须通过直属 `ProductFolder` 对象 ID 精确消歧。若目标目录内仍存在多个同名 Product，报错阻止。
- **系列目录（ProductFolder）约束**：
  - 上传端**严禁创建**任何 `ProductFolder`；目标系列目录必须在 CAXA 设计树中预先存在，缺失时在任何上传/建 Part/建 Product 之前阻止。
  - 预检登录后通过只读 `product_folder_index` 读取一次实际目录树并在当前 helper 会话内缓存，按图号字母段与目录名中的拉丁字母动态匹配：
    - 普通系列：`HX21 → HX系列`、`HE → HE系列`、`HGB01` 等嵌套路径按层级匹配 `HT合同特殊/HGB系列`，其余 `03.HT.*` 匹配 `HT合同特殊`；
    - 指定特例目录：`LSYZ → LSYZ两室一站`、`GPZ → GPZ钢瓶组`、`QT → QT其他成品`、`SFC → SFC防爆箱`、`SFD → SFD防爆箱`；
    - `OM`、`OV`、`OW` 统一自动映射到 `OW系列`；
    - 顶层精确目录 `NS` 仅自动匹配 `03.NS.*`；历史目录 `NS防爆箱` 不参与自动匹配（如 `03.CFS.*` 等需手工指定）；
    - `03.W6.*` 为设计区域例外，不做自动系列映射，界面显示“未指定系列”，需操作员手动设置 `W6` 及核对设计树；
    - 未连接 CAXA 离线状态时可用 `<字母>系列` 作临时占位，预检返回实际目录后自动覆盖，但本地占位不得作为最终归属依据。
- **多台 `03` 整机与工艺文档汇总**：
  - 同一批次可包含多台 `03` 整机，层级树按 `产品目录 → 系列产品 → 整机 Part` 分组展示，每台 `03` 行独立编辑产品名称（仅修改本地计划，不修改已有 CAXA 对象）。
  - 仅有 `J03/M03/P03/T03/Z03` 工艺文档、没有对应 `03.*` 整机图时，仍根据工艺文档的 `machine` 收集目标并支持补建 `既有系列目录 → Product → 整机 Part`；`Z03.*` 工艺文档与其作为借用父级的 `03.*` 节点在层级树中归入同一系列产品分支，借用子件位于整机下。
  - GPZ 产品名称允许包含 `/`（如 `两瓶钢瓶组 L2-25/40`）；`Z03` 总装明细表不因目录规则而自动挂接成借用。

## 5. `02` 半成品规则

- `02.*` 半成品属于 Product `02 半成品`；`J02/M02/P02/T02/Z02` 等工艺文档必须受支持，且不能套用 `03` 的系列产品名称规则。
- **点号上级查找**：如目标 `02.A36.02.AR02` 按点号层级从最近上级 `02.A36.02` 开始向上查找 CAXA 中唯一存在的 Part 上级；若目标末级 Part 缺失而既有上级与 Product `02` 均存在，仅在最近的既有 Part 上级下补建缺失的末级叶子 Part。
- **严禁越级/多归属**：
  - 不得把 `02.x.*` 末级直接挂到 Product `02 半成品` 下，也不得自动创建新的 `02.x` 分组；Product `02`、点号上级缺失或存在多个同名原件时，预检与上传均阻止。
  - 同一 `02` 图号只能有一个 `Part` 原件，允许存在多个借用挂接，但只允许一个 `reference=False` 非借用归属；存在多个非借用归属时写前阻止。

## 6. 物料编码（`MaterialNo`）与图纸属性

- 新建或复用所有业务 Part（通用件、`02` 半成品、`03` 整机）时，均需确保其 CAXA 属性 `MaterialNo` 等于该 Part 自身图号；已有值不一致时自动更新并回读确认。
- 上传 `Z03.*` / `Z02.*` 等工艺文档时，宿主的物料编码仍保持 `03.*` 或 `02.*` 的 Part 图号，**绝不**把 `Z`/`J`/`M`/`P`/`T` 工艺编号写入 Part 的 `MaterialNo`。

## 7. 上传执行、重复策略与弹窗守卫

- **暂存一致性**：实际上传只读取本任务独占暂存目录中按图号目标名存放的副本，并在上传前再次复核 SHA-256 与文件大小；不改写、不移动用户源文件。
- **默认追加版次（`append_iteration`）**：
  - 重复策略默认为「升版」（在现有版本上追加新的版次），显式选择「复用」（`reuse`）才直接复用既有文档；
  - 写后必须执行刷新回读（EAP `Refresh()` 优先、必要时短等待后二次读取）验证版次实际递增且对象 ClassID 符合要求（Drawing `1002` / CappDocument `1003`）；未增长则标为待核实，禁止重放写入。
- **状态拦截与反审规则**：
  - 处于**“发布”**状态或被他人检出的图纸不允许追加版次，写前直接拦截报错（不静默转为 `reuse`），保留其余可传图纸继续处理并在最终阻止自动发流程；
  - **反审退回图纸**：即使历史流程关联（`DocumentOfWFInstance`）仍在，只要图纸当前状态已回到**“设计”**，必须允许继续追加版次，禁止仅凭历史流程关系拦截。
- **弹窗自动确认严格边界**：
  - 仅在对应命令作用域、且目标弹窗**同时满足精确标题、正文关键文本、唯一匹配窗体、以及属于当前 helper 进程 PID** 时才允许自动确认，严禁跨进程点击用户手工操作弹出的弹窗。
  - 包括四类守卫：`导入文件确认对话框`、`对象已经存在提示框`（必须通过 UI Automation 操作真实控件并回读验证“追加新的版次”选中状态后才可点确定）、登录“同一个用户已经登陆（`0x83060607`）”提示框，以及 helper 自身删除关系确认框。

## 8. 审核打印流程

- **前置门禁**：本批任一文件失败/待核实、任一关系失败/冲突/缺失/待核实、或文档类型/数量校验不完整时，**严禁**自动发起审核打印流程。
- **关联范围**：流程必须关联本批已确认的全部 Drawing（`1002`）与 CappDocument（`1003`），不得遗漏工艺文档。
- **固定模板与角色参数**：`WFTemplate = 1`、`WFProcessTemplate = 31`、`process_def_id = "2"`、`activity_def_id = "4"`，默认审核人 `Person ID = 66`（`审核账号`）。
- **独立「发起审核打印」按钮**：
  - 与“上传完成后自动发起流程”复选框互不影响；
  - 仅基于本地日志中已确认成功的上传与关系记录补发流程，**绝不重传 PDF、绝不补建关系**（本地 PDF 已移动或删除也不阻止发起）；
  - 若同一批次此前已有已确认流程，仅对尚未被既有已确认流程覆盖的新增已确认文档另起流程；
  - 启动后必须回读流程实例 `state = 2` 及全部 `WFInstanceWithDocument` 关联文档，回读不完整或失败则记为待核实（保留已创建的流程实例 ID）。

## 9. 防重、待核实恢复与仅限本批新建借用的原地撤回

### 9.1 批次身份与异常恢复

- **稳定批次身份**：同一界面清单生成稳定 `batch_id`，与服务器/端口/用户名组成任务身份；仅修改勾选状态、补充工艺文档或单独补发流程不重传已确认文档；若同一图号的文件内容 SHA-256 发生变化，则失效该行确认状态并重新上传。
- **禁止重放待核实写入**：进程崩溃、管道超时、写后回读异常等结果不明的操作统一记为“待核实”（`OP_PENDING` / 原 `OP_RUNNING`），阻塞再次自动执行写入，直到人工核实完毕。
- **统一“核实待定结果”窗口**：
  - 界面层只展示图号、关系端（`父级 ← 子级`）、流程实例 ID 等业务文字，**严禁**要求现场人员手填内部 Object ID / ClassID，也不暴露 `upload:stage` 等内部代码；
  - 支持在单个列表窗口中多选操作执行「自动回读所选并确认成功」或「确认未写入」（并支持仅当前批次匹配时的一键直接重传），全部回读连接与检查在后台线程执行，不卡死 Tk 主界面。

### 9.2 仅限本批新建借用的原地撤回（四道硬护栏）

为解决同批上传期间因人工拖拽/关联操作把组件借用到错误父级后的现场勘误需求，上传树支持右键执行「**撤回 CAXA 借用（仅限本批）…**」，但必须同时满足以下四道安全限制，其余情况一律禁止开放删除/解绑能力：

1. **仅限本批新建借用边**：只允许撤回 `link_type == "borrow"`（`reference=True`）且当前批次 `journal` 明确记录 `created_by_batch=True` 并完整带有 `parent_id`、`child_id`、`link_id`、`link_class_id` 的关系；历史已有借用（`"已存在"`）与 `reference=False` 归属关系**绝对禁止**撤回。
2. **流程锁定即禁止**：同一任务日志中一旦存在已确认或待核实的审核打印流程记录，立即阻止借用撤回。
3. **待核实先行阻止**：任务存在任意待核实操作时，必须先完成核实恢复，期间禁止执行借用撤回。
4. **写前/写中双重校验**：写入前按 `parent_id` 实时回读 `link_endpoints`，校验精确 `link_id` 存在且 `reference=True`；helper 侧 `CmdUnlinkPartRelation` 同时启用 `require_reference=True` 第二防线。撤回失败且是否解绑不明时记为 `OP_PENDING`（`relation_unlink_uncertain`）；确认已解绑后日志更新为 `OP_UNLINKED` 且不删除任何 Part/图纸实体，也不自动复活该边。

## 10. 分发更新、工具演进与外部模块边界

- **安装命名与自动更新**：
  - 本地安装 EXE 固定命名为 `图纸上传助手.exe`，版本通过 `VERSION`、`app/version.py`、Git tag（`vX.Y.Z`）及 UI 标题展示。
  - 正式 EXE 每天首次启动在后台静默检查 GitHub `/releases/latest` 正式版（忽略草稿与预发布），发现更高版本且具备有效 `sha256:` digest 时按钮变为「下载 vX.Y.Z」；校验通过后利用更新模式先备份旧 EXE、再原子替换原安装路径并清理 `_PYI_*` / `_MEIPASS*` 后重启，保持桌面与开始菜单快捷方式长期有效。
  - 更新下载期间及存在未安装更新时阻止新任务写入；下载完遇到运行中任务则等待 `busy` 结束后再重启覆盖。
  - EXE 暂未进行 Authenticode 代码签名，发布说明需如实标明。
