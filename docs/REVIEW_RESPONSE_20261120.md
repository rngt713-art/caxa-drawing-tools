# v1.1.0 上传端复审处理记录

日期：2026-11-20  
复审来源：`CAXA图纸工具_v1.1.0_上传端复审_20261120.md`

## 本轮已处理

### P0 批次选择变化创建新任务

- 增加稳定 `batch_id`，随上传包保存。
- 勾选/取消勾选、追加新行和 workflow-only 子集继续使用同一任务。
- 成功上传记录保存 SHA-256；同图号内容变化时重新上传，不误用旧确认记录。
- 回归覆盖：
  - 上传 A 后追加 B，只上传 B；
  - 上传 A+B 后只选 A 发起流程；
  - 未勾选行变化不改变任务身份。

### P0 更新下载可中断上传

- 更新下载/安装期间阻止上传、手工借用和单独发起流程。
- 下载完成时若仍有 CAXA 任务运行，只记录“更新待安装”，任务结束并解除 busy
  后才启动新版。
- Tk 回归覆盖 `busy=True` 时下载完成不启动更新线程。

### P1 更新替换顺序

- 先复制并校验新版临时文件；
- 复制并校验旧版 `.old-时间戳` 备份；
- 最后使用一次 `os.replace(temp, old)` 原子替换安装路径；
- 失败时恢复旧文件。
- 重启仍使用原安装路径和原文件名，并清理 PyInstaller `_PYI_*` 环境；
  桌面和开始菜单快捷方式继续有效。

### P1 helper 剩余部分写入

- `CmdCreateProduct()` 的目录挂接异常保留 Product ID。
- `CmdLinkPartCore()` 高层写入异常后不再自动执行低层重复建链。
- `CmdSetDrawing()` 和 `CmdUnlinkPartRelation()` 使用结构化写后证据。

### P3 损坏更新状态

- 非法缓存版本视为“没有缓存更新”，不会阻止上传端启动。

### GPZ 特殊系列

- `03.GPZ.*` 固定映射到既有目录 `GPZ钢瓶组`。
- 不再自动生成不存在的 `GPZ系列` 并要求现场手改。

## 仍未处理或受外部条件限制

- Authenticode：当前没有可用证书，上传端和 helper 仍未签名。GitHub SHA-256
  只能证明资产与 Release 一致，不能替代独立发布者签名。
- 更新下载进度、取消、代理、镜像和离线选择 EXE：本轮未实现。
- 新版启动握手和自动回滚：仍按复审 P3 判断，不在本轮必要范围。
- `C:\Program Files` 等只读目录：自动覆盖会明确失败并保留旧版；当前仍要求
  部署在用户可写目录。
- CI、PE FileVersion 资源和 tkinterdnd2 资源裁剪：本轮未实现。

## 结论

本轮优先解决了会导致重复上传、流程找不到任务、更新中断上传和关系重复写入的
问题，并加入 GPZ 历史目录映射。签名和安装器级加固仍需证书及独立发布流程。
